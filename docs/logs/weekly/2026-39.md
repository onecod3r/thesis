- **09-22 (same day):** two bugs found running it for real, both fixed —
  `np.savez_compressed` silently appending `.npz` broke the stream-cache
  rename, and the GPU parity assertion failed (5e-4 vs. 1e-4 tolerance) not
  from a real bug but because cuDNN uses a different kernel for one
  whole-sequence GRU/LSTM call than for a loop of single-frame calls; fixed
  by checking parity on CPU (1.6e-6), where that kernel-selection difference
  doesn't exist.
- **09-22 (same day):** ran end to end, 0 failures, and the result reversed
  the working assumption. The raw position-binned aggregate looked weak
  (`gru` early/mid/late 0.05/0.14/0.21) and seemed to confirm the
  per-frame-supervision worry — but it conflated two regimes. Splitting by
  fresh-start vs. un-reset-carryover (added as a new notebook cell, §3b)
  showed a **fresh** start already reaches 0.58 confidence by its late third
  (`gru`, matching the whole-video numbers from `five-arch-benchmark.md`),
  while a **contaminated** one stays near 0.01→0.05→0.09 throughout — `dnn`
  (no persistent state) shows almost none of this gap, pinning it on carried
  recurrent state specifically. Consistent with Phase B (oracle reset cuts
  bleed-through 19.6→0.8 frames for `gru`) and Phase D (`gru` beats `lstm`
  at every threshold/hold setting). **Verdict: the per-frame-supervised
  retrain (Phase C) is downgraded from prerequisite to optional refinement**
  — the real lever is wiring reset into any live inference loop, which
  `RecurrentSession` already does correctly. `docs/reports/streaming-confidence.md`.
