Results:
- Every parameter passes (p < 0.005). Selected fingers 0.81 (chance 0.17); repeated movement 0.80;

  to 70%. Handshape alone gives 26.1%.

- `export_web.export` gained `ship: "fp32"|"int8"|"mixed"`, **default now `mixed`** (int8

  doesn't compound the way the decoder's does across beam steps: 34/40 exact vs
  `generate()`, **same guard-acceptance as full fp32 (24/40)**, ~730 MB vs fp32's ~1 GB.
- `guarded` preset (browser-only; `team` stays frozen): `num_beams` 4→2 (~16% faster,
  33/40 outputs byte-identical to beam=4, guard-acceptance 23/40 vs 24/40 — beam=1 was
  ~50% faster but dropped to 19/40, too much), `max_length` 64→56 (margin above the
  checkpoint's observed max gloss length of 55 tokens over 330 sentences, p99 44).
- Considered and **not shipped**: WebGPU (onnxruntime-web execution provider). No way to
  drive a real browser against a GPU backend here to verify it helps or even works;
  shipping it blind risks breaking what currently works. Left as a documented option
  (TODO §13) for whoever can test it with a real browser.
- `apps/web/test/speech.test.ts` now runs `fp32`/`int8`/`mixed` as three variants.
- One self-inflicted bug caught before it shipped: an early config edit put a `_comment`
  key inside `generate.guarded` (a dict unpacked straight into `model.generate(**gen)`),
  which crashed `fixtures`. Fixed (moved to a sibling `guarded_note` key) — but the first
  `assets` export had already run against the broken intermediate config, so the deployed
  manifest carried a stray (harmless but sloppy) `_comment` string. Caught by inspecting
  the live manifest after deploy, not by luck; re-exported and redeployed the ~4 KB fix.
