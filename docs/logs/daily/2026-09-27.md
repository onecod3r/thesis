## 3. `recognition_2` error analysis, retune, and a no-pose-vs-with-pose ablation (TODO §14)

Analyzed §1's `records.json` in depth: found two real bugs (`major_location`'s Hand/Head check used a
median instead of a min, washing out brief touches — `Hand` predicted 5/1,308 times against 108 true;
fixed to match `contact`'s existing min-based check) and retuned three thresholds (`spread_t`, `amp_t`/new
`apt_amp_t`, `flat_base_t`) from confusion-matrix evidence. Net: `spread` +0.067 and `major_location`
+0.019, but `flexion` −0.028 and `minor_location` −0.017 on the full 233-gloss sample despite the
`flat_base_t` change fixing the 2 anecdotal examples it was based on — flagged as a retune-on-the-eval-set
caveat, not claimed as an unambiguous win.

User then asked for the same 233-gloss test with pose landmarks added (prioritizing hands/face, pose only
filling gaps: mid-shoulder anchor, `Body`/`Arm` location categories, a wrist fallback for `movement` when
the hand drops out of the nucleus) — "I want to see if discarding pose is feasible or does pose add a
significant benefit." Building it surfaced a second real bug: the `Arm` check first compared a hand to its
own (ipsilateral) elbow/wrist, which nearly always registers "close" since a hand's own wrist landmark is
the same joint as its own pose wrist — `Arm` fired on 729/1,414 clips against ~24 true. Fixed to the
contralateral elbow (ASL-LEX's `Arm` means touching the *other* arm). Also fixed a unit confound: the pose
variant was scaling every threshold by shoulder width instead of inter-eye distance, silently desensitizing
every distance check, not just the pose-specific ones.

**Result, with both bugs fixed**: every hand-internal parameter shows exactly 0 delta between no-pose and
with-pose (confirms pose isn't quietly doing more than asked). `major_location`'s new `Body`/`Arm` fire
correctly but too rarely to move the number (Δ −0.001). `movement` gets measurably *worse* with pose
(0.492 → 0.377) — its wrist fallback triggers 37% of the time on a spot check (more often than expected;
GISLR's hand tracking has real gaps even within a clip's own detected span) and the pose wrist is
evidently a worse proxy for ASL-LEX's hand-path-based Movement parameter than even a gappy hand-centroid
signal. **Answer to the user's question: discarding pose is feasible — nothing tested benefits from it, and
the one substantive pose-based mechanism tried makes a parameter worse.** Full write-up:
`docs/reports/recognition2-phonology-rules.md`. TODO §14 updated; next action is the user's review.

## 5. Individual sign recognition mode (TODO §15, new)

User asked for a second, separate mode: deploy whichever model scores best for *individual* sign
recognition (not continuous sentences), with a custom stop condition — a sign is complete when the hand
leaves the frame — then, mid-implementation, added an early-commit rule too: if the top-1 guess has already
held steady, commit right away rather than waiting for the hand to leave. Offered the cheaper option (plain
`gru`, already export-ready) vs. the harder one (`gru_phono_raw`/ME_134, 0.7632, needs a new Keras port);
user picked the harder one.

Built the missing export path: `PhonologyFrontend` had no Keras/TFLite port at all (`sb.recognize.export
.keras`'s `BUILDERS` only covers plain `gru`/`lstm`/`bilstm`/`cnn1d`). Added `_phono_tf` to
`sb.recognize.export.step` — a TF-ops port of its `forward` (mode `"phono+raw"`), verified against
PyTorch's `forward_all` on 200 synthetic frames: **max prob diff 1.19e-6**. One real snag: `tf.linalg.cross`
has no TFLite builtin kernel; replaced with the explicit 3-vector formula. Isolated classifiers (plain
`StreamingGRU` head, no cosine head/null class/boundary) got their own simpler export path
(`_build_isolated_step_module`/`export_web_isolated`) since the Linear head's weights bake straight into
the graph — no external class matrix needed. 3.83 MB TFLite.

Browser side: new `apps/web/src/pipeline/isolated.ts` — a session that feeds frames to the isolated model
and commits on either trigger (hand-gone for 4 frames, or top-1 stable for 8 frames at ≥60% confidence),
with a 12-frame refractory window so the stable-repeat rule can't fire twice on one held pose. Wired
additively into the existing sign→speech page as an "Individual sign mode" checkbox, running alongside
(not replacing) the continuous C4 pipeline. `npm test` (11/11) + `npm run build` passed; deployed via
`wrangler deploy`. **Not done**: the 4/8/0.6/12 constants are first guesses, untested against real footage
or any held-out data — no ground truth exists for "when should a sign commit" the way GISLR has ground
truth for classification. Full write-up: TODO §15.
