## 1. An architecture review, checked against the code (§9)

An external review proposed a Git/DVC/MLflow stack and a `signbridge/` workspace
layout. Checking each claim against the repo rather than accepting it:

**Confirmed.** Runs recorded no commit, environment or dataset version. Feature
caches were keyed by subset *name*, so editing an index list in `subsets.py`
silently reused the old array. 675 MB of weights lived on one machine after 8
runs' weights were already lost. The npz contract was prose. The training stack
hardcoded GISLR. `index.csv` had drifted to 38 rows against 43 folders.

**Corrected.** The review said the two feature pipelines collided and broke the
"all else identical" guarantee — they did not (distinct `_nan_` suffix), and the
leaderboard metric was never at risk because the eval script reads raw parquet
and never touches a cache. The hazard was to *training inputs*, which is bad
enough. It also called the `.gitignore` negation "silently defeated"; it was
verifiably working (`src/data/*` globs contents, so `!src/data/models/` held).

**Rejected.** MLflow — a second write path for data `meta.json` already holds,
whose payoff is a plotting cell over `index.csv`. DVC — its one advantage over
content addressing is what §9.2 buys directly.

## 3. §9.8 — the workspace restructure

Filed as deferred (5,532 LOC, one developer, no tests), then overruled and
executed. The prior reasoning is kept verbatim as §9.9.

```
packages/{sb-core,sb-extract,sb-recognize,sb-mlops,sb-rescore,sb-synthesize}
experiments/{extraction,recognition,synthesis}/   registry/   data/   apps/   ops/
```

Beyond a file move, three things actually changed:

1. **`features/` became a real split** — `cache.py` owns addressing; `base_v1`
   and `firstplace_v1` expose the *same* four-function surface, so they are
   substitutable, and the `pipeline=`/`nan_policy=` kwargs stopped threading
   through every call site.
2. **The dependency direction is enforced by the manifests**: `sb-mlops` depends
   on `sb-core` only, never on `sb-recognize` — the registry has to be readable
   without importing torch.
3. **`CWD = src/` is retired.** Packages install editable; `sb.core.paths` walks
   up for the workspace marker.

Nothing was rebuilt: 29 GB of caches and 6.4 GB of POPSIGN landmarks moved by
rename, and all three cache keys are byte-identical. Renamed to **signbridge**
(project and docs only — the folder and git remote were left alone, because
renaming them breaks `.venv`'s absolute paths and the kernel spec for no gain).

**Caught in review:** the first wiring named a local `source`, shadowing
`train_run`'s existing `source` parameter — the driver-notebook name recorded as
`training.source`. `ty` caught it; there is now an assertion on that field.

## 4. R2 was never available

`sb-sync` had a provider the account cannot use. It now dispatches on
`SB_ARTIFACT_BACKEND`, sharing the manifest, hashing and verification:

- **`kaggle`** (new default) — a **Kaggle Model**, one variation per run
  (`bracu23101281/signbridge-checkpoints/pyTorch/run-<id>`). The argument is not
  storage: this repo already authenticates to Kaggle (`whoami` →
  `bracu23101281`), so there is no new account or secret, and a Kaggle inference
  kernel can attach a model directly — the backup and the artifact a submission
  run loads (§6.3) become the same object. **Models rather than Datasets** was
  the correction that mattered: a Dataset versions as one directory, so every
  push would re-send all 707 MB and every restore would pull the lot; a Model's
  variations version independently, so a push uploads only the new runs and a
  restore fetches exactly one checkpoint. Each variation carries its run's
  `meta.json` beside the weights.
- **`local`** — external drive, NAS share, or a synced folder. Zero deps.
- **`s3`** — any S3-compatible endpoint (B2, Wasabi, MinIO, Storj, or R2 later).

Verified end to end on `local`: 42 objects pushed, one checkpoint deleted and
restored **byte-identical**, and a deliberately corrupted backup copy **refused**
on sha256 with no half-written `.pt` left behind. Test artifacts were then
removed, so the committed manifest still honestly says nothing has been pushed.

## 5. The 42 checkpoints are on Kaggle, and off this disk

Uploaded as `bracu23101281/signbridge-gislr` — 42 runs, **16 variations**,
versions in chronological run-id order:

```
bracu23101281/signbridge-gislr/pyTorch/gru-me126-xy/2
└─ owner ──┘ └─── model ────┘ └─fw─┘ └ variation ┘ └ver┘
```

The mapping falls out of the registry rather than being invented: a *variation*
is `<architecture>-<subset><-coords>` — precisely what makes two runs
incomparable — and a *version* is that same configuration retrained. So
`gru-me126-xy` reads 0.7471 → 0.7565 → 0.7565 and the version history **is** the
training history. Versions are chronological, not ranked; "which run to deploy"
stays `sb-promote`'s question.

Every version carries its run's `meta.json` beside the weights, so an uploaded
checkpoint is self-describing.

**Deleting the local copies was the part that needed care.** `sb-sync prune`
downloads each remote copy and unlinks the local file only when three hashes
agree — the manifest's, the remote's, and the local file's. The third is not
redundant: a local file that has diverged from what was uploaded is something
the remote does *not* have. The manifest was committed **before** the first
deletion, because deleting files while the only record of where they went is
untracked is the 2026-07-18 reset one step removed.

Result: **42 verified, 0 refused, 707 MB freed.** `last.pt` for the 41 finished
runs went separately (`drop-resume`, 675 MB) — the registry never resumes a
finished run. Run `1784459817` keeps its resume state: it stopped at epoch 50 of
300. The registry now holds **zero checkpoints locally**.

Proven from a cold cache afterwards: pulled `1784447175` back, sha256 verified,
and `torch.load` returned the expected bilstm/ME_126/xy at 0.7569.

Two things only doing it for real surfaced. The module docstring still described
the Datasets approach — wrong on three counts after the switch. And `prune` was
about to free 707 MB from the registry while kagglehub quietly accumulated the
same bytes in `~/.cache`, which would have defeated the entire exercise; it now
clears its own verification downloads.

**Consequence:** a run folder no longer contains weights. `sb-evaluate` and the
TFLite export now begin with `sb-sync pull <run_id>`, and the eval script says
so rather than raising `FileNotFoundError`.
