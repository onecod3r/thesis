# 2026-09-18 — landmark-importance notebook run, results write-up

`gislr.1.models.landmark-importance.ipynb` (TODO §3.3, built 2026-09-16) was
run end to end by the user: 5-fold OOF training + final fit + held-out
`test.csv` evaluation + landmark-ranking pass, for all three architectures
(DNN/GRU/LSTM). This entry covers the post-hoc analysis and write-up.

## 1. Results read-out

Test accuracy: DNN 71.02% (weakest per-class robustness, 33 classes <50%),
LSTM 70.55% (most balanced, only 16 classes <50%), GRU 67.96% (the only model
that scored *worse* on test than its own OOF validation). Landmark ranking:
all three architectures independently put hand fingertips at the top and
face landmarks last (region means: hands ~0.95–0.97, pose ~0.72–0.75, face
~0.44), reproducing the ME-126 subset decision from a third, model-derived
method. Cross-architecture Spearman ρ on `ranking_score` is >0.8 for every
pair. Full detail, tables and figures: `docs/reports/landmark-importance.md`.

## 2. New diagnostic: per-axis (x/y/z/speed) saliency — not in the notebook

The notebook's attention gate and `sb.recognize.interp.importance.
gradient_saliency` both collapse each landmark's 10 feature channels
(position/velocity/acceleration × xyz + speed) into one number, so there was
no way to answer "which axis does the model rely on" from its saved outputs.
Wrote a standalone analysis script (not committed — see §4) that reuses the
already-cached `final.pt` checkpoints and the existing 400-video importance
sample (same seed) to compute gradient×input saliency *without* collapsing
over the channel axis, then grouped into x/y/z/speed. Finding: z carries
15–24% of saliency mass vs 36–49% each for x/y — same direction as the
motion-energy report's z-noise finding but a much smaller gap, so it's a
partial cross-check, not a restatement (open follow-up in the report, §6).

Also pulled hidden-layer weight histograms straight from each `final.pt`
(sanity check — all unimodal/zero-centered, no dead or saturated layers) and
per-class accuracy + top confusion pairs from the saved `test_predictions.npz`
per architecture, since the notebook itself only saves confusion matrices as
images, not a per-sign table.
