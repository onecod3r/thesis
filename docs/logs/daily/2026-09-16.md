# 2026-09-16 — GISLR moves to the self-produced GISLR_Stratified dataset; canonical split reset

Reconstructed from commits `2613426` and `1def9bd`.

## 1. Dataset switch (`2613426`)

- `gislr_dir()` now does a normal `kagglehub.dataset_download` of `bracu23101281/gislr-stratified`:
  one `(T,543,3)` npz per sequence plus `train.csv`/`test.csv`. `sign_to_prediction_index_map.json`
  is derived on first use. `base_v1`, `firstplace_v1` and `evaluate.py` read npz; `pyarrow` is
  no longer needed.
- **Landmark-order bug in the source npz:** it wrote pose/face/left/right, not this repo's
  canonical order that every `subsets.py` index array assumes. Fixed by a fixed permutation
  (`sb.recognize.features.gislr_stratified.CANONICAL_TO_STORED`), checked on a synthetic npz.
- **Canonical split reset.** The fixed 80/20 split (18,896 val) replaces the self-computed 90/10
  (9,448 val). The 37 previously evaluated runs are historical references only.
- README, CLAUDE.md, TODO, `schemas/meta.v4.json` and `index.csv` updated; the old `asl-signs`
  kagglehub cache was deleted from disk.

## 2. Local test scoring replaces Kaggle submission (`1def9bd`)

`test.csv` is the held-out set, so `evaluate_run` marks `submission = {tested: true,
platform: "local"}` itself (without clobbering an existing tested record). The evaluation
notebook's Kaggle submission queue (§8) was removed and the TFLite export reframed as a plain
deployment export. The first three runs on the new pipeline (gru; ME_126, ME_132, FP_118) were
committed, confirming the switch works (`n_val` 18,896).

## 3. Follow-ups

The `motion-energy` and `subset-comparison` notebooks broke (they read raw parquet). See
`2026-09-19.md` for what was done about them.
