# 2026-09-19 — feature-discriminability notebook: built, run, analyzed

`gislr.0.dataset.feature-discriminability.ipynb` (TODO §3.4) went from
request to a written-up result in one day: built (angles + kinematics
feature pipeline, tolerance-band metric), smoke-tested against real data,
run by the user (Scope A + Scope B), then analyzed and reported.

## 1. Build

New `sb.recognize.interp` modules: `geometry.py` (normalization extracted
out of `features.py`, no behavior change to `landmark_interp_v1`),
`kinematics.py` (`landmark_kinematics_v1` — gap-preserving interpolation,
Savitzky-Golay jitter, rolling variance, 28 joint angles, reduced to a flat
per-video descriptor dict), `discriminability.py` (F-ratio, probe classifier,
and a new tolerance-band overlap metric). The notebook loads npz directly
(`gislr_dir()`), since the old `subset-comparison.ipynb` this track
complements is broken post-2026-09-16 dataset migration (DuckDB/parquet,
TODO §0.1).

Smoke-tested against real GISLR data before handoff (not just synthetic):
Scope A (30 real videos) and a shrunk Scope B (~1,200–4,500 real videos)
both ran end-to-end. This caught a real bug — never-detected landmarks have
a trivially zero-width tolerance band, which gamed the per-feature ranking
into reporting them as "perfectly tight." Fixed by gating the per-feature
top-N tables on `F > 0`.

## 2. Run + a second instance of the same bug, caught in analysis

The user ran the notebook end to end (Scope A: 3 classes × 10 videos; Scope
B: 15 classes, 4,497 videos). Analyzing the executed outputs turned up the
**same bug at the aggregate level**: the type/region breakdown cell (§11)
never had the `F > 0` gate applied to it, only the per-feature top-N tables
did — so it was silently ranking `detection_rate` and `meta` as the
tightest-separated feature *types* (driven by 33 constant, never-detected
landmarks + one constant `valid_frame_frac`), which contradicted their low
F-ratio. Patched the notebook cell to apply the same gate, re-ran it against
the cached Scope B parquet (no new video processing needed), and re-embedded
the corrected output/figure into the notebook.

## 3. Findings (full detail: `docs/reports/feature-discriminability.md`)

**Angles are the most information-dense feature type by a wide margin.** A
probe on the 56 joint-angle features alone reaches 68.3% accuracy (15
classes); position-only (3,258 features) reaches 79.4%. Adding angles to the
full feature set gains +2.5pt (79.6% → 82.1%) for just 56 extra features —
the single highest-value block in the pipeline per feature spent. The
top individual feature by F-ratio, beating every raw landmark coordinate, is
`angle_R_palm_facing_mean` (hand orientation) — exactly the kind of
"handshape" signal joint angles were added to capture.

The tolerance-band overlap metric agrees with F-ratio on *which* features
are good but is much flatter across types in aggregate (0.97–1.0 for
everything informative) — every top individual feature still has
`worst_pair_overlap == 1.0`, meaning no single feature separates all 15
classes; that needs the full probe (82.1%).

One open question, not resolved today: region ranking (pose last, hands
first) diverges from every prior region ranking (motion-energy,
subset-comparison, landmark-importance all found hands > pose > face here
pose ranks below face). Filed as a follow-up — plausibly a 15-class-sample
artifact or a descriptor-choice difference (raw mean position vs the
`x_std`/speed descriptors that made pose look informative before).
